# 퍼스널 컬러별 화장품 찾기

배포 주소: https://yeseo-i.github.io/personal-color-makeup/

## 1. 프로젝트 소개

- **목적**: 퍼스널 컬러 톤(봄 웜·여름 쿨·가을 웜·겨울 쿨)별로 분류된 립스틱·블러셔·아이섀도 색상을 둘러보고, 사용자 추천 글을 톤별로 기록하는 사이트이다. 사용자에게 맞는 톤을 진단하거나 정해 주는 사이트는 아니다.
- **대상 사용자**: 색조 화장품을 고를 때 톤을 기준으로 둘러보고 싶은 소비자이다. 자신의 퍼스널 컬러에 맞는 화장품을 찾는 사람뿐 아니라, 원하는 분위기에 따라 다른 톤의 메이크업을 시도하려는 사람도 포함한다.
- **페이지**: 컬러별 화장품(계절·제품군 필터로 셰이드 보기), 사용자 추천(글 작성·삭제).

## 2. 실행 방법

- **배포 주소**: 접속하면 `site/`로 이동한다.
- **로컬 실행**: 저장소 루트에서 `python3 -m http.server 8000`을 실행하고 http://localhost:8000/site/ 를 연다.



## 3. 데이터와 분류 기준

**출처**: Makeup API([https://makeup-api.herokuapp.com/](https://makeup-api.herokuapp.com/))의 Kaggle 사본(https://www.kaggle.com/datasets/oftomorrow/herokuapp-makeup-products). API가 503을 반환해 사본을 썼다.

**분류 단계**: HEX 색상 코드를 CIELAB(D65)으로 변환해 판정한다. 'L*'는 명도, 'C*'는 채도, h°는 색상각을 뜻하며, 기준 값은 `scripts/color_rules.py`에 있다.

| 단계 | 기준 | 처리 |
|---|---|---|
| 1. hex 형식 | `#RRGGBB` | 아니면 제외 |
| 2. 저채도 | C* < 10 | 제외 |
| 3. 노랑·초록·파랑 | 75 ≤ h° < 290 | 제외 |
| 4. 웜/쿨 | 30 ≤ h° < 75 | 웜, 나머지 쿨 |
| 5. 계절 | L* 55, C* 50을 경계로 사용 | 웜: L* ≥ 55 봄, 미만 가을 / 쿨: L* ≥ 55이고 C* < 50 여름, 나머지 겨울 |

**근거**: 웜/쿨 개념은 Carole Jackson, Color Me Beautiful(1980)을 참고했다. Kim과 Kim(2020, Asian J Beauty Cosmetol 18(3), [https://doi.org/10.20402/ajbc.2020.0055](https://doi.org/10.20402/ajbc.2020.0055))은 립스틱 색과 퍼스널 컬러의 관계를 다룬 연구로 참고했다. 계절별 수치 기준은 조사한 범위에서 찾지 못해 프로젝트용 임시 규칙으로 설정했으며, 분류 정확도는 검증하지 않았다.

**결과** (`clean_products.py` 실행)

| 제품군 | 셰이드 | 봄 웜 | 가을 웜 | 여름 쿨 | 겨울 쿨 |
|---|---|---|---|---|---|
| 립스틱 | 1,666 | 226 | 308 | 230 | 845 |
| 블러셔 | 301 | 101 | 26 | 106 | 62 |
| 아이섀도 | 446 | 107 | 53 | 34 | 45 |

전체 개별 색상(셰이드) 2,413개 중 잘못된 HEX 37개, 저채도 129개, 노랑·초록·파랑 계열 104개를 제외하고 2,143개를 분류했다. 최종 데이터에는 분류 가능한 색상이 하나 이상 있는 제품 239개가 포함된다.

## 4. 작업 과정

1. **데이터 출처 검토**: API 대신 Kaggle 사본을 원본으로 정했다.
2. **정제와 분류**: 정제 스크립트와 분류 규칙 파일을 만들었다.
3. **화장품 탐색 페이지**: 계절·제품군 필터와 이미지 대체 처리를 구현하고, 소개 문구와 4계절 안내 카드를 추가했다.
4. **사용자 추천 페이지**: 추천 글 작성·저장·삭제 기능을 구현했다.
5. **검증**: 제조사 색상 라벨과 비교하는 스크립트를 작성하고, 분류 결과를 확인했다.
6. **GitHub Pages 배포**: 루트 `index.html`이 `site/`로 이동하게 했다.


## 5. Claude Code 활용 증거

**1. 데이터 정제·분류:** 수집에 실패하면 임의 데이터를 만들지 말라고 지시했고, API가 멈췄을 때 그대로 지켜졌다.
```text
Makeup API 서버가 세 제품군 모두에 503 Service Unavailable을 돌려줍니다.
그래서 임의 데이터는 만들지 않았고, data/raw/는 비어 있습니다.
```

**2. 분류 결과 검증:** 제조사 라벨과의 비교 결과를 확인하고, 결과가 예상과 다르더라도 분류 기준의 숫자를 임의로 변경하지 않도록 했다.
```text
웜/쿨 일치는 14/17이고, 분류 제외는 4개예요.
규칙(color_rules.py)과 data/products.json은 그대로예요.
```

**3. 화면 기능 구현:** Claude Code는 브라우저로 화면을 볼 수 없어서, 확인하지 못한 항목을 따로 보고했다. 화면은 내가 직접 확인한 뒤 커밋했다.
```text
이 환경에는 브라우저와 Node가 없어서 JavaScript를 실제로 실행해 보지는 못했습니다.
```
## 6. 검증 결과

**구현 검증**: 정제 스크립트를 두 번 실행해 통계가 같았고, 결과 파일이 커밋된 `data/products.json`과 바이트 단위로 같았다. `check_labels.py`가 다시 계산한 17개 셰이드의 계절도 `data/products.json`과 모두 같았다.

**타당성 참고 비교:** 립스틱·블러셔·아이섀도 중 제조사가 셰이드 이름에 언더톤을 적은 셰이드(Blue-Toned, Warm, Cool Tones 등)를 모두 골라 웜/쿨 판정과 비교했다. Pure Anada 아이섀도의 (C)·(W)는 Cool·Warm으로 해석했고, 언더톤 설명인지 애매한 이름과 뉴트럴 표시는 제외했다.

- 결과: 채점한 17개 중 14개 일치. 4개는 규칙상 분류 제외 색(저채도, 파랑·노랑 계열)이라 채점하지 않았다.
- 불일치한 3개:

| 셰이드 | 라벨 | h° | 판정 |
|---|---|---|---|
| NYX Fire | 쿨 | 30.14 | 웜 |
| NYX Matte Warm Brown | 웜 | 23.39 | 쿨 |
| NYX S.O.S | 쿨 | 65.66 | 웜 |

Fire와 Matte Warm Brown은 웜/쿨 경계(h° 30) 근처에서 갈렸고, S.O.S는 채도가 낮은 브라운이라 색상각만으로는 언더톤을 구분하기 어려운 경우이다. 계절은 라벨에 없어 채점하지 않았고, 표본이 작아 정확도를 판단할 수는 없다.


**화면 확인**: 브라우저에서 확인했다. 계절·제품군 필터, 대체 이미지, 빈 칸 등록 차단, 새로고침 후 글 유지, 삭제.

## 7. 잘된 방법과 어려웠던 점

**잘된 방법 3가지**
- **단계별로 맡기고, 직접 확인한 뒤 커밋**: 한 번에 다 시키지 않고 데이터 → 페이지 → 추천 → 검증 순으로 나눴다. 매번 결과를 보고 승인한 뒤에만 커밋하게 해서, 문제를 단계마다 잡을 수 있었다. 특히 분류 결과의 통계를 확인해 실제 데이터 수와 분류 결과가 맞는지 점검할 수 있었다.
- **CLAUDE.md에 작업 규칙 기록**: 원본 데이터 보호, git add . 금지, 기준값 변경 금지, push는 승인 후에만 같은 규칙을 적어 뒀다. 덕분에 작업할 때마다 같은 주의사항을 반복해서 전달하지 않고도 정해 둔 기준에 따라 작업할 수 있었다.
- **"모르면 멈추고, 확인 못한 건 확인했다고 하지 말 것" 규칙**: API가 503일 때 Claude Code가 임의 데이터를 만들지 않고 멈췄고, 브라우저로 볼 수 없는 항목은 "확인하지 못함"으로 구분해서 보고했다. 이 규칙이 없었다면 실제로 확인하지 않은 데이터를 사용하거나 기능이 정상 작동한다고 잘못 판단할 수도 있었다.

**어려웠던 점 3가지**
- **퍼스널 컬러 분류 기준의 근거 부족**: 제품별 계절 라벨과 수치 기준을 뒷받침할 근거를 찾기 어려웠다. 임시 기준을 정한 뒤 제조사 라벨과 비교했고, 비교 대상을 17개로 확대해 14개가 일치하는 것을 확인했다. 하지만 이 결과만으로 전체 분류의 정확도를 판단할 수 없어, 분류 기준의 타당성을 충분히 검증하지 못한 점이 한계로 남았다.
- **Makeup API 오류**: 데이터 수집 중 API에서 503 오류가 발생해 데이터를 가져올 수 없었다. 임의의 데이터를 만들지 않고 Kaggle에 공개된 데이터 사본으로 대체해 작업을 이어갔다. 이후 API가 복구된 뒤 데이터를 비교한 결과, 세 제품군의 데이터가 모두 일치했다.
- **사용자 추천 글 공유 기능의 한계**:  다른 사용자와 추천 글을 공유할 수 있도록 구현하고 싶었지만, 무료 서버의 일시 정지 가능성과 연동 설정을 고려해 localStorage를 사용했다. storage.js를 교체해 다른 저장 방식으로 확장할 수 있도록 설계했지만, 현재 글은 같은 브라우저에서만 확인할 수 있다.

## 8. 알려진 한계

- 분류는 검증하지 않은 임시 규칙이며, 경계값 근처 셰이드는 작은 차이로 판정이 바뀐다.
- hex 값만 쓰므로 실제 발색과 다를 수 있다.
- 2016~2018년에 수집된 해외 쇼핑몰 데이터이다.
- 일부 상품 이미지는 열리지 않아 대체 이미지로 표시된다.
- 추천 글은 작성한 브라우저의 localStorage에만 저장되고 다른 사용자와 공유되지 않는다.
